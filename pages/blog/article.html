这不是一个单纯的 Canvas 动画实验。 真正想解决的问题是：如何让动态背景拥有生命感， 同时又不破坏网页本身的阅读体验。

01. 一个不应该静止的背景

很多网页的背景最终只有两个功能：填充颜色，或者承载图片。 它们通常是静止的，因此用户在浏览页面的过程中， 很难感受到页面本身存在任何“生命”。

而我希望 HealthJian 的背景能够成为一个长期存在的数字环境。 它不需要抢占正文的注意力，也不应该制造大量复杂动画。 最理想的状态，是让用户在不经意之间感受到页面正在缓慢呼吸。

02. 粒子的缓慢流动

粒子的速度被控制在一个非常低的范围内。 如果运动速度过快，它们会变成一种明显的视觉特效； 如果完全静止，又失去了存在的意义。

所以这里选择的是一种接近环境变化的运动速度。 用户并不会持续关注某一个粒子， 但当他停留在页面数秒之后，会意识到整个空间仍然处于缓慢变化中。

最好的动态效果，并不是让用户注意到动画， 而是让用户在动画消失时意识到：原来刚才的空间是活着的。

2.1 聚合与散射

当鼠标靠近粒子时，并不是简单地把所有粒子吸向鼠标。 这种做法虽然直接，但很容易形成一个明显的粒子团， 并且当鼠标停留时间过长时，所有粒子可能失去原来的空间结构。

因此交互力被设计为一个局部柔性磁场。 粒子受到吸引，同时加入轻微的切向运动， 于是它们会产生类似流体环绕的感觉。

particle-interaction.js 
const force = 1 - distance / radius;

const pull = force * attraction;
const orbit = force * rotation;

particle.vx += pullX + orbitX;
particle.vy += pullY + orbitY;

// 始终回归基础运动
particle.vx += (baseVx - particle.vx) * damping;
particle.vy += (baseVy - particle.vy) * damping;

2.2 如何避免粒子失控

最重要的一层机制是：每一个粒子都必须拥有自己的“目标位置”。 鼠标交互只能暂时改变它的位置和速度， 不能永久改变粒子的空间归属。

这意味着，即使用户把鼠标停留在一个位置很长时间， 粒子也不会全部堆积到那里。 当交互力减弱之后，它们仍然会重新向自己的目标位置回归。

03. IP 图像的粒子化

下一步是将 HealthJian 的 IP 形象加入背景系统。 这里并不直接把原始 PNG 放到页面右侧， 而是先对图像进行采样， 再把采样结果转换为大量粒子的目标坐标。

于是这个 IP 角色本质上不再是一张图片， 而成为整个粒子系统的一部分。

STEP 01
Canvas 绘制原始 IP 图像，并读取像素数据。
STEP 02
根据透明度和亮度筛选有效像素，并降低采样密度。
STEP 03
为每一个粒子分配唯一的 homeX / homeY。
STEP 04
鼠标仅产生局部扰动，粒子最终回归 IP 轮廓。

04. 日夜模式的连续变化

Day 与 Night 并不是两个完全独立的页面。 如果直接切换 CSS 颜色，会产生明显的状态断裂。

因此背景颜色、粒子颜色、连接线透明度， 甚至页面 UI 的玻璃层， 都通过统一的 progress 参数进行插值。

05. 阅读界面与背景共存

背景系统最终必须让位于内容。 所以文章区域没有采用传统厚重的大白色卡片， 而是尽可能减少容器的边界。

正文像是悬浮在动态空间中， 但通过字体、行距、颜色和宽度建立足够稳定的阅读层级。

左侧目录则保持固定， 它不再是传统意义上的“侧边栏卡片”， 更像是一条轻量的阅读导航轨迹。

FINAL THOUGHT

06. 最终结论

一个优秀的动态背景，不应该只是“炫技”。 真正重要的是，它需要有自己的秩序、回归机制和交互边界。 粒子可以短暂地因为用户而改变， 但整个系统仍然应该保持自己的结构。
